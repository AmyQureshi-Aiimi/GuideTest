# Collection Types

Collection Types are customised collections to suit a business process. Certain users are able to create collection types and assign them to others to use.&#x20;

You will be able to:

* Track the progress of a collection using statuses that match your process steps. See tasks that need to be completed as part of each status to guide you through the process.
* Apply tags to an item to add context and reminders for an item.&#x20;
* Share the collection with specified users or teams to improve security and reduce risk.

***

## Managing Collection Types

1. Go to your Collections.
2. Select Actions and Manage Collection Types.

From here you can see all of your available collection types, edit them and create new ones.&#x20;

***

## Creating Collection Types

1. Go to Collections.
2. Select Actions and Manage Collection Types.
3. Select New Collection Type.

### Basic Details

1. **Name:** Enter a name for the collection type.&#x20;
   * This must be 50 characters or less.
2. **Description:** Enter a description for the collection type.
   * This could be what the type is for, how or when to use it.
3. Select Continue to Statuses.

### Statuses

You can create statuses that match the journey of your business process. You can create a core journey and exceptions to these. \
New, In progress and Done statuses are applied to all types to get you started. These can be edited or deleted by selecting the Status Menu.

#### Creating a Status

1. Select New Status
   * This will open the New Status modal.
2. **Type** - Select the type of status.
   * Core - This sits in the main desired path of a process.
   * Exception - This is a sub status. For example within the In Progress core status, Researching may be an exception status.
3. **Name** - Enter a name for this status.
   * This must be 50 or less characters.
4. **Category** - Choose a category for this status from the dropdown.
   * Active, Inactive and Closed.
5. Select Create Status.
6. Select Continue to Result Tags.

<figure><img src="../../.gitbook/assets/image (17).png" alt="" width="375"><figcaption></figcaption></figure>

#### Arranging your statuses

You can arrange the statuses using the order arrows to match your process. The statuses are ordered first to last.

A status can be edited or deleted by selecting the Tag Menu.

### Result Tags

Result tags can be added to a result. These could help others understand why a result is in a collection, what actions have or, should be performed on a result, etc.

A result tag can be edited or deleted by selecting the Tag Menu.

1. Select New Result Tag.
   * This will open the Result Tag modal.
2. **Name** - Enter a Name for the result tag.
   * This must be 50 characters or less.
3. **Description** - Add a Description to help users know when to use this tag.
   * This must be 100 or less characters.
4. Select Create Tag
   * This will close the modal.
5. Once you have all your result tags select Continue to Tasks.

<figure><img src="../../.gitbook/assets/image (277).png" alt="" width="375"><figcaption></figcaption></figure>

### Tasks

Create tasks that should be done as part of this collection type. These are helpful reminders on things that need to be completed and steps that must be completed. Please note: The tasks do not need to be completed within Aiimi Insight Engine to progress.

1. Select New Task.
2. **Name** -  Enter a Name for the task.
   * This must be 50 or less characters.
3. Description - Explain to users what needs to be done for this task.
   * This must be 400 or less characters.
4. **Related Status** - Choose what status a task sits within to guide users.
   * If no status is selected the task will be a general note or task that can be completed at any time.
5. Select Create Task.
6. Select Continue to Permissions.

<figure><img src="../../.gitbook/assets/image (18).png" alt="" width="375"><figcaption></figcaption></figure>

### Features

You can add additional features to your collection types. This is only redaction of items within a collection at the moment.

1. **Allow documents to be redacted** - Check this to allow items to be redacted within collections of this type.
   * You can control the users that are able to redact information within a collections sharing settings.
2. **Import storage configuration** - Choose a source from the dropdown list to store uploaded items.
   * If this is left blank, users will not be able to upload items to this collection.

<figure><img src="../../.gitbook/assets/image (19).png" alt="" width="375"><figcaption></figcaption></figure>

### Permissions

You can choose who is able to use and see collections of this type. This can be extremely helpful when creating a Right To Be Forgotten, HR process collections or any other type with sensitive information.

### Allow All Users

1. Select All Users if this collection should be available to all.
2. Select Create Collection Type.

### Limit User Access

1. Select Specified Users to limit and choose the users that can use this collection type.
2. Enter the users who can use this collection type within Users.
   * Select the add button or the enter key on your keyboard.
3. Check Share all collections of this type...&#x20;
   * This will mean all new collections of this type will also be shared with the specified users.
   * Leave unchecked to allow collection creators to decide who this is shared with.

### Publish

Once created it still wont be able to be used until it is published.

1. Select the collection types action menu
2. Select Publish.
